# Software Testing Portfolio

## Overview

This repository contains portfolio artifacts from **CS 320** focused on unit testing, test automation, and quality assurance. The work included here demonstrates how I implement requirement-driven services and verify functionality using automated tests.

---

## Project One – Service Implementations

For Project One, I developed and tested three in-memory services:

* **Contact Service**
* **Task Service**
* **Appointment Service**

Each service enforces validation rules defined by the requirements, such as required fields, length limits, immutability, and date constraints. JUnit tests were written to verify correct behavior, reject invalid input, and prevent regressions.

---

## Project Two – Summary and Reflections

This repository also includes the **Summary and Reflections Report** from Project Two. The report explains my testing approach, how I selected testing strategies based on requirements, and what I learned while developing and maintaining unit tests across multiple services.

---

## Testing and Design Approach

I focus on enforcing requirements directly in code and validating behavior through automated unit tests. Tests are written to cover both valid and invalid scenarios, helping catch defects early and maintain consistent behavior as changes are made.

Services are designed with clear responsibilities and testability in mind. Writing tests alongside development influenced cleaner design and more predictable logic.
